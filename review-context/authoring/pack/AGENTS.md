# Plan-authoring and execution boundary

This is a sealed specification/plan input, not the discovery implementation repository. Preserve it after seal. The user authorized repair and verification of this successor plan only. No runtime implementation, authenticated discovery, provider calls, production, remote Git writes, signing or real review launch is authorized by this artifact.

Canonical tasks are docs/tasks/task-manifest.v6.3.6.json. Task Markdown is generated by plan_tools/render_task_cards.py; regenerate it after changing the manifest. Artifact, command and consumer inventories are generated by plan_tools/finalize_contracts.py. Run plan_tools/check_plan.py and plan_tests before sealing. plan_tools/seal_plan.py writes only a new plan delivery and external attestation; it is distinct from the future runtime seal tool.

During separately authorized implementation: one task and evidence record at a time. No automatic per-task commits. BOOT0 Git initialization and P08 zero-parent export need explicit local Git authorization; host review-key bootstrap and human fresh-session attestations need explicit host-review authority. A missing prerequisite yields HOLD. Never silently replace missing tools, commands, roots or vector obligations.

Only MIG0-owned synchronization tasks generate vendor, schema-lock, native dependency locks, review-config and task-command-registry bindings. Runtime implementation remains in the separately authorized authoring/runtime root. Generated test JS is separate from extension/dist; test privileges cannot enter production output.
