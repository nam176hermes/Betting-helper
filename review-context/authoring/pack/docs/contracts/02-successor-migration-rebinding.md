# MIG0 ownership, input and exact output layout

MIG0 alone copies the 209-file pinned baseline, applies delivery rebinding, synchronizes normative assets, regenerates command/config bindings, refreshes native locks and runs the legacy scan. Source commit/tree and every file size/hash are frozen in baseline-source-files.v1.json; required clean/no-remote checks run before any copy. Never copy .git, local caches, .venv, node_modules, live evidence or untracked files. Generated vendor/schema-lock/task-registry files are recreated from the normative mapping, not copied as active inputs.

version-rebinding.v1.json lists exact paths, before/after SHA-256 and ordered literal replacements. Before hash permits one application; after hash is an idempotent no-op; any other bytes fail. Replacement cannot be re-applied to an already rebound prefix. Legacy scan evaluates exactly those outputs and the explicit exceptions. No implicit file glob, blanket textual replacement or undocumented exception is permitted.

Delivery version is v6.3.6; inherited wire-protocol URNs, cryptographic domains, signed fixture expectations and their v6.2 package-source provenance stay byte-compatible. This is not an implicit protocol upgrade. Every exception is enumerated by path and expected bytes in the registry or immutable inherited-source mapping. Upgrading that protocol requires a separately reviewed amendment and regenerated golden signatures/hashes; this plan does not authorize it.

Normative mapping has two disjoint namespaces: immutable inherited entries map to vendor/hybrid-discovery-v6.3.6/{schemas,graphs,security,sql,vectors,registries,cdp}/...; new plan entries map to vendor/hybrid-discovery-v6.3.6/docs/... exactly. New schema references therefore use vendor/.../docs/schemas. No inferred extra docs component. Inherited schema $ref anchors are normalized to equivalent existing JSON Pointers by plan_tools/normalize_inherited_schemas.py; schema-pointer-normalization.v1.json enumerates every spelling change and the source map pins both original and normalized hashes. All other constraints, identifiers, domains and inherited vector bytes stay unchanged. Only two declared graph overrides are allowed; any other destination collision fails.

Initial tooling and candidate copy: MIG0-T01..T06. After all P01 materialization, MIG0-T07 synchronizes exact plan/config bytes, refreshes uv/pnpm locks using the native offline commands, verifies unchanged dependency versions, installs the frozen offline toolchain and compiles the crash harness before P03. After P03/P04/P05, MIG0-T08 performs final synchronization, config/command generation, lock checks and legacy scan before P06. These are explicit recurring MIG0 tasks in the task DAG, not an out-of-phase writer. Consumers may invoke only checks; they do not update MIG0 outputs.

Native locks are never hand-edited. An unavailable offline dependency or changed dependency version yields HOLD. No network fetch follows automatically. The normative source-map/seed lists are frozen plan inputs and materialization cannot invent new entries.

VERIFY_FINAL_MIGRATION is an explicit final MIG0-T08 command. The registry final_legacy_policy applies to every copied baseline migration output and imported historical fixture. Initial before/after file hashes apply only at MIG0-T03; later declared source adaptations are accepted only with the appropriate modifier task evidence, not by accepting arbitrary observed bytes. Scan the frozen regex tokens in each source against its finite per-file allowed_literals plus the two exact fixture literals; unlisted source tokens fail. Historical fixture files require exact SHA256. Unmodified copied files still require their rebound hash. Config outputs require supplied config hashes. Native locks require unchanged exact dependency versions and the MIG0-T07 receipt hashes. The final receipt binds all inspected outputs, source owners, accepted evidence and comparisons. P06 owns only new validation implementation; it cannot change these migration outputs.

The final receipt uses migration-receipt.schema.json#/$defs/FinalMigrationReceipt. checked_outputs is sorted by UTF8 logical path with no duplicates and covers the exact policy scope; owner_task/evidence_sha256 bind the accepted owner receipt (MIG0-T03 for unchanged rebound copies, the mapped writer for other bases). Its content_hash is SHA256(b"HD636/MIGRATION-FINAL/v1\0" + RFC8785 JCS of the record without content_hash). Wrong scope, absent receipt, mismatched output hash, unaccepted task or duplicate output fails.

MIG0-T06 is a post-adaptation checkpoint: first validate the MIG0-T03 task evidence against every declared before/after patch hash, then validate current outputs against accepted modifier evidence completed so far (MIG0-T04/T05). It must not demand that a semantically adapted file still equals its earlier literal-only hash, or demand behavior assigned to later P02/P05 tasks. No later writer evidence is eligible at this checkpoint. The same finite legacy token policy applies; modified bytes without an accepted, declared modifier fail. MIG0-T08 repeats this check including the later accepted adaptations and native lock receipt.
