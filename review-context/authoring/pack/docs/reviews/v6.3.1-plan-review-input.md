# Independent plan-contract review of Hybrid Discovery v6.3.1

## Verdicts

```text
PLAN_CONTRACT_COMPLETE: NO
TASKS_EXECUTABLE_BY_FRESH_CODEX: NO
FINDING_COVERAGE_COMPLETE: NO
SECURITY_REVIEW_CONTRACT_COMPLETE: NO
AUTHORIZED_PRODUCTION_PHASES: NONE
```

The review verified the ZIP sidecar, all 30 manifest entries, all 38 task-card/JSON pairs, dependency identifiers, predecessor ordering, and the supplied v6.2 source hashes. Missing implementation was not itself treated as a defect. The blocking defects were plan contradictions and unresolved implementation choices.

## Blocking findings

### V631-C1 — Circular internal self-review binding

The final self-review was required to bind a manifest and ZIP that were produced only after the self-review was placed inside the pack. A self-excluding manifest did not remove the ZIP self-reference. The repair must use an acyclic governed-content root and an external final ZIP attestation.

### V631-C2 — Materialization lifecycle conflict

The exactness gate required zero unresolved files, symbols, schemas, and commands before later phases created many of those artifacts. Release and aggregation tools also appeared after candidate export/review. The repair must distinguish declaration, materialization, executable-reference, qualification, and sealing states, with all release/review tooling present before candidate qualification.

### V631-C3 — Successor migration lacks a complete owner

No task owned rebinding of v6.2 vendor destinations, schema locks, command registries, working directories, hashes, and versioned identifiers. The repair must add an explicit MIG0 phase with one normative source, deterministic synchronization, command regeneration, legacy-reference scanning, and a migration receipt.

### V631-C4 — Exact references remain non-exact or invalid

The plan retained placeholder symbol prose, aggregation path placeholders, unresolved JSON Schema anchors, and required artifacts with no task owner. The task schema also did not by itself prevent production authority, placeholder commands, unknown dependencies, empty rollback, or task-count mismatch. The repair must assign every artifact, freeze every command input, use resolvable schema pointers, and specify a semantic validator.

### V631-C5 — Verification topology does not prove promised coverage

Python test discovery covered only bootstrap tests, TypeScript configs excluded the crash harness, and the crash-vector/harness mapping plus clock failure precedence remained deferred. The repair must freeze test discovery/build configurations, exact command registries, crash mappings, clock precedence, and a proof-coverage matrix.

### V631-C6 — Cybersecurity review aggregation is not decision-complete

The adversarial command set, reviewer launch authority, signer trust source, workspace/process independence, freshness, and review aggregation were not fully specified. Different run-ID strings alone were not evidence of independence. The repair must define host-issued launch authorizations, isolated review workspaces, exact cybersecurity commands, execution receipts, freshness, and deterministic aggregation. Mechanical isolation can be proven; model-context freshness remains a human-attested procedural requirement and must not be misrepresented as cryptographically proven.
