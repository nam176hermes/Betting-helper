# Artifact ownership and source freeze

artifact-ownership.v1.json is the complete producer/consumer inventory. A baseline source is an exact file pinned by the supplied manifest or baseline-source-files registry, not a directory assumption. BOOT0 seeds pack files using seed-artifacts.v1.json and preserves the full sealed plan under authoring/plan-input. The original sealed input is never modified. MIG0 copies runtime baseline source; P01-T02 owns creation of every new runtime source/test stub, including all release/review/security tools and restart inspector. Later implementation tasks are explicit permitted modifiers and qualification owners. They do not become second creation owners.

Generated outputs have a generator task/command and exact source mapping. External evidence, delivered files, host bootstrap records and review outputs are declared separately and are not required by MATERIALIZATION_COMPLETE. Task exact_files may name inputs; outputs must use the owner/modifier set. Every command operand and schema/symbol/test reference is checked against the inventory and the transitive dependency graph. Directory operands resolve to the explicitly enumerated member sources; they are not wildcard permission to create artifacts.

P05-T09 implements/qualifies runtime tooling formerly assigned to P07/P08/P09. Those phases now perform operations only. P06 validators are the last runtime source changes; P07 qualifies the final source/config/dependency/build root. Later evidence is external. Normative source/config bindings freeze at MIG0-T08. Any subsequent source/config/lock/normative change invalidates P07 and requires a new candidate, export, seal and review cycle.

Task evidence roots and scratch locations are exact registry inputs. Failed attempts remain available; this plan authorizes no deletion, destructive rollback, history rewrite or remote write. The task manifest uses NO_COMMIT_WITHOUT_SEPARATE_USER_AUTHORIZATION; Git initialization/zero-parent creation requires explicit operator approval during later execution. Spec repair has not executed any such operation in the real authoring/runtime roots.
