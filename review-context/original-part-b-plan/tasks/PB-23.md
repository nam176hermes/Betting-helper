## Error handling and continuation
Ordinary test/code errors are fixed automatically; then continue the next ready task. A missing key/profile/approval/platform is WAITING_INPUT with one precise user instruction, not a request after every task. Run other ready independent tasks meanwhile. Never treat synthetic data as a substitute for a real-case gate. Authentication failure, scope mismatch, secret leakage or an unsafe privilege change is a stop for the affected real source. Quota/runtime limits never auto-expand.

## Rollback
Stop owned source/session if needed, preserve evidence, and revert only this task’s change through a normal reviewed commit. No hard reset, force push, deletion of other work or mutation of old PASS receipts.
