optimized traces demonstrate the relevant Serena calls. Full exposure filtering remains a
separate unproven option, not a silently applied restriction.

## E. NORMAL regression root cause

The original **6 → 8 native tool-item** change is exactly:

- +1 full code-work skill read: useful/required compliance; retained through preload.
- +3 symbolic calls: overview, references, body. References/body provide relevant assurance;
  overview is unnecessary when the task already names `valid_port`.
- −2 broad shell inspection blocks: useful reconnaissance was replaced with more precise tools.

There was also a pure orchestration/discovery call not represented as a native leaf item.
The after search matched `name + description`, returning **24 descriptions, 22,867 description
bytes**, in a 24,796-byte result. Before initially matched two tool names and later inspected
one more description. The after run then serialized initialization, activation, skill reading
and symbol-body retrieval across more requests. **5 → 9 requests replayed the fixed startup
context**, overwhelming the smaller first prompt. Extra narration was secondary: +280 bytes.

COMPLEX reduced requests from 6 to 4 by reusing bounded scope and batching more work. Its old
after run also omitted some symbol/reproducer steps present before. The task oracle passed,
but we do not treat fewer checks as intrinsically better or remove mandatory steps to imitate
that trace. Cache effects explain why its total-input improvement did not reduce uncached input.

Final revision residuals remain visible: Astra C2 separated patch and validation into different
requests; Terra D-new used two name-confirmation rounds and still emitted some duplicate MCP
representations. The final profile improves the original Terra regression, but does not
universally enforce the most economical model execution sequence.

## F. Context/profile changes implemented

The operational architecture is unchanged. Changes are limited to:

1. `scripts/codex_task.py`: M/N merged prompt, verified instruction-presence map, full required
   skill preload/hash, capability-name hints, actual fresh preflight summaries, exact helper
   command syntax, concise check stdout, and brief worker-output defaults. C/D full prompt and
   policy remain unchanged. Routing, risk floors, ownership/freshness and formal rejection remain.
2. Three active nested `AGENTS.md` bridges: less duplicated policy prose, with native fallback,
   critical verification, independence and authority/HOLD language retained.
3. `docs/codex/workflow.md`: actual profile behavior, evidence limits and commands.
4. `scripts/analyze_codex_context.py`: offline component/request/cache analysis, unique-response
   counting and first-task scope so later resumes are not double-counted.
5. `scripts/benchmark_codex.py`: failed quality or nonzero evaluation exit now gives a nonzero
   benchmark process exit. Explicit case/variant selection now limits each command to one evaluation;
   there is no default eight-run matrix. These close false-success and accidental-quota-spend paths.
6. `scripts/test_codex_task.py`: additional coverage for prompt preservation/preload, brief-vs-full
   evidence, benchmark failure propagation and usage deduplication/resume scope.

| Profile | Included | Deferred / retained on demand |
| --- | --- | --- |
| M | Exact target/ownership/files, basic authority, V0/V1 plan, concise output | Unrelated architecture/review prose; all applicable capabilities remain available |
| N | Bounded subsystem context, V1/V2 plan, required skill, named semantic tools, fresh selected prechecks | Unknown-symbol overview and other tools only when evidence requires them |
| C | Full Phase 2 context, contracts/decisions and required architecture capabilities | No Phase 3 prompt shortening |
| D | Full critical constraints, authority, negative checks, review requirements and HOLD | No reduction of critical reasoning or verification floors |

Prechecks are selected, not an automatic full-suite bootstrap. One failing oracle ran before
each final-profile dispatch and is counted separately. `-B` prevents Python bytecode from
invalidating the prepared dirty-state snapshot; the oracle's source and behavior are unchanged.

M/N uses low model verbosity and FINDING / EVIDENCE / ACTION / RESULT / OPEN ISSUE, normally
five short fields. Required skill announcements, meaningful progress and material failures
remain. These defaults improved output but are not a hard interceptor of every model choice.

The final profile adds **one non-model precheck invocation** per C2/D-new run. Every corner
also has one independent post-run oracle invocation. Native tool-item counts exclude these
harness checks, pure `functions.exec` discovery and internal subprocesses; they are not total
operating-system command counts. The ledger and results preserve those boundaries.

Same initial source/oracle bytes, same installed Codex 0.153.4, explicit model/effort arguments,
disabled child-agent spawning, no production access. Global config preservation is **not verified**. C2/D-new
use `-B` only to avoid cache artifacts and carry actual precheck evidence. One sample per final
corner; paths, cache state and model behavior were not randomized. B's framework/cleanup choices
are part of the observed bundle, not a stable causal coefficient for the model family.

Final preservation caveat: `config.toml` changed during the benchmark window and contains trusted
project entries for all four disposable fixtures. Neither the helper nor the executed harness
writes this file; the evidence is consistent with runtime project registration, but the original
config body was not retained, so other changes cannot be excluded. The machine AGENTS hash is
unchanged. No global config restoration was attempted because ownership of concurrent changes
is unknown. This weakens causal isolation and remains an explicit limitation of the comparisons.

[crossover.json](phase3-evidence/crossover.json) retains all four new results, actual argv,

## L. Final verdict

**PHASE 3 PARTIAL — SOME EFFICIENCY ESTABLISHED**

The original NORMAL regression is explained, selected duplicate context is removed, the final
Terra profile improves its measured comparisons, and mandatory capabilities/assurance remain.
The Astra result is mixed and there is no longer-task comparison; Phase 3 completion and net
system-level efficiency are not claimed.

Remaining work, in priority order:

1. Resolve the observed remaining name-confirmation and patch/validation round trips while
   preserving tool availability checks, patch failure handling and mandatory verification.
   Any further experiment must state the unresolved hypothesis and required comparison first.
2. Once same-model synthetic acceptance is met, evaluate one longer useful local task against
   a credible controlled/historical equivalent. Do not substitute this phase's local fix for it.
3. Keep formal propagation held until its separately authorized preparation. Consider exposure
   filtering only with task-specific evidence; global capability removal is not justified here.

Validation and preservation are recorded in [validation.json](phase3-evidence/validation.json):
five focused tests, Ruff/format and strict mypy for all four operational Python files;
bridge idempotence; source/route preservation; eight historical counter reconciliations;
four-call ledger; fixture oracles; global-config hashes and nested Git status/HEAD checks.
Runtime application code and its Phase 1 static debt (Ruff 28; mypy 163 across 29 files) remain
unchanged. Portable/full qualification was not rerun for this external tooling/instruction
change and is not claimed current. Phase 1/2 evidence artifacts remain intact.
