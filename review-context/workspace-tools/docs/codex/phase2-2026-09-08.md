## D. Operational subagent policy

Normal target: coordinator plus 0–2 workers. Before dispatch assess independence, already
loaded context, duplicate discovery, expected parallel benefit, and mandatory review role.
Use a bounded TASK / EXPECTED OUTPUT / CWD / HEAD-DIRTY OWNERSHIP / FILES-SCOPE /
CONSTRAINTS / VERIFIED FACTS / AUTHORITY / CHECKS / DO NOT RE-READ / EXIT packet.
No full-history fork is needed when that packet suffices. Workers return FINDING / EVIDENCE /
IMPACT / ACTION / OPEN ISSUE. Separate formal reviewers remain independent.

The helper validates bounded packets, disables worker child agents, rejects overlapping
implementation roots/scopes, and requires a reason above two concurrent workers. Its eight
worker maximum follows host capacity. This is a per-batch default, not a safety cap or a
global scheduler. The coordinator dispatches independent work, continues useful work, then
collects when a dependency requires the result and integrates once. The batch consumes
completion futures without model polling. Native collaboration waits stay within 60 seconds
and do not trigger empty status narration. Waiting with no independent work is legitimate.

## E. Final risk-based model router

Six axes (0–2): ambiguity, blast radius, failure cost, cross-system coupling, novelty, safety.

| Class | Deterministic rule | Applied route |
| --- | --- | --- |
| CRITICAL | Critical flag; safety >0; failure cost=2; or security/authority/persistence/recovery/clock area | Astra high |
| COMPLEX | Otherwise any axis=2 or sum >=5 | Sol medium; Astra medium when ambiguity or novelty=2 |
| NORMAL | Otherwise nonzero score or area floor >=V2 | Terra medium |
| MECHANICAL | Remaining deterministic low-risk work | Luna low |

Critical flags explicitly include live/financial, credentials/authentication, persistence,
recovery/checkpoints, concurrency/idempotency, kill switches/order state/state ownership and
irreversible migration. Small patches do not lower this classification. Live/financial flags
also force V4; other critical work has at least V3 plus review.

New evidence escalates via a fresh packet with revised scores/flags and an old/new route
decision. Resolved C/D implementation may de-escalate to Sol medium only with a matching
scoped decision-file hash, no unresolved questions and deterministic implementation declared.
Risk, verification floor and required review remain unchanged. Review cannot use that escape.
This records routing, not a change to the current coordinator's model. No fabricated model
cost multiplier or recommended maximum Astra call count is used.

## G. Concrete tool/context changes

`prepare` binds exact CWD, HEAD, dirty ownership, scoped bytes, hierarchy/config/policy hashes.
`read` bounds scope/range/output and reuses an identical read. `check` executes an explicit
argv, retains full logs, bounds the tail and rejects unexplained identical retries. A later
failure invalidates an older pass. `resume` emits only target/HEAD/ownership/status/facts/
decisions/inspected files/completed and remaining checks/questions, and rejects stale state.
`launch` applies the router and reinjects policy. `batch` consumes completions. `close` can
only report local plan status; governed/review work stays HOLD.

Packets/state are transient, not another permanent context book. Environment labels and
all relevant inputs must be declared: the helper does not fingerprint the entire machine.
Raw tools remain possible and are visibly responsible for some benchmark overhead.

lookup/collision behavior across modules, and a read-only synthetic idempotency review.
Both variants received identical disposable source and an unchanged oracle, with no provider
access, dependencies, real credentials or production behavior. Baseline used frozen Phase 1
guidance and Astra/high; optimized used bounded packets and risk routing. This tests the
bundle, not the isolated effect of a prompt, model or flag. Each side had child agents disabled.

| Shape | Before → after route | Tool calls | Output bytes including MCP | Quality |
| --- | --- | ---: | ---: | --- |
| mechanical | Astra/high → luna/low | 6 → 5 | 15,365 → 15,145 | PASS / PASS |
| normal | Astra/high → terra/medium | 6 → 8 | 15,415 → 24,917 | PASS / PASS |
| complex | Astra/high → astra/medium | 9 → 6 | 20,066 → 15,470 | PASS / PASS |
| critical | Astra/high → astra/high | 5 → 4 | 16,805 → 17,060 | PASS / PASS |

Aggregate: **26 → 23 tool calls (11.5% fewer)**, but **67,651 → 72,592 output bytes
(7.3% more)**. Recorded input tokens were **659,049 → 809,721**; recorded output tokens
**3,075 → 3,709**. These counters include model/cache effects and cannot be converted into
account quota savings. The evidence does **not** establish net quota reduction.

The harness launched eight Codex worker processes, at most two concurrently; these are
eight paid/subscription model evaluations, not free coordination. A separate native resume
probe and the failed old-executable availability probe are outside the paired results.
Each evaluation had one host turn, zero native child-agent spawns, zero collaboration waits/messages and zero
exact repeated shell commands. Those coordination zeros were controlled in both variants;
they do not measure improvement against the historical 1,900-wait workload. Command-pattern
test invocation proxies and one independent oracle invocation per case are retained per run.
Exact internal model turns, complete files-inspected counts, semantic retries and all MCP
read duplication are **NOT AVAILABLE** from exec JSONL. No numbers were fabricated for them.
No unexecuted historical replay is labeled measured.

All eight runs reported truncated skill descriptions due to the skills context budget.
The normal optimized run additionally read the approximately 7.3 KB code-work skill and
used Serena; mandatory skill/tool compliance must not be removed to make metrics look better.
The observed regression warrants a scoped context/profile experiment, not an automatic
model downgrade or global plugin removal.
